- **Hospital Node runtime skeleton — IMPLEMENTED:** [`instances/hospital-node/`](../instances/hospital-node/README.md) is a FastAPI app with pinned dependencies and pytest tests (use case, HTTP, layer boundaries). One codebase runs one process per hospital: each instance loads its hospital identity (node and organization ids), port, and local storage location from the JSON file named by `HOSPITAL_NODE_CONFIG`, and refuses to start without a valid one (HC-112, D2). Fictional demo configurations exist for Hospital A, Hospital B, and the private practice. `GET /health` (HC-111, D2) is a liveness check reporting the configured identity, its `patient_history`, `audit_events`, and `access_grants` capabilities, the clinical repository's record counts, and a notice of what is MOCKED. It serves the patient history API (HC-114, D2), its side of [`hospital-node-federation.v1.yaml`](../contracts/federation/hospital-node-federation.v1.yaml): `GET /v1/federation/node` and `POST /v1/federation/queries`. A query is parsed strictly (`400`), its authorization is checked before any record is read and denied by default (`403`, same answer whether or not the patient is known), and only entries inside the requested scope are returned, each naming its source node. The authorization check is MOCKED (see Mocked behavior). Every query the node answers or refuses is recorded in its own audit trail (HC-116, D2), served by `GET /v1/audit/events` per [`hospital-audit-events.v1.yaml`](../contracts/api/hospital-audit/hospital-audit-events.v1.yaml) with filters by patient, query, and outcome: events name the requester, purpose, scope, authorization, and disclosed record references, never clinical content, and nothing is disclosed if the event cannot be recorded. The trail is kept in memory only (lost on restart) and its readers are not authenticated. It serves the access grants API (HC-115, D2) per [`patient-access-grants.v1.yaml`](../contracts/api/patient-access/patient-access-grants.v1.yaml): list a patient's grants with their status (`active`, `expired`, `revoked`), record one, and revoke one; the node enforces them in its patient history API at once. The grant store is MOCKED (in memory, seeded from the fictional `access.json`, lost on restart, never shared with other nodes), and its callers are not authenticated. Tests, ruff, and Hospital A and B running side by side on ports 8101 and 8102 were checked; the three demo nodes running with the Federation Service in `http` mode returned Patient A's `complete` timeline over real HTTP, every node answered `denied` for another purpose, and discovery reported each node `discovered`; each node's audit trail then listed its own `disclosed` and `denied` events with the Federation Service's `query_id`. Nothing uses its storage location yet, and it is not deployed.
- **Hospital-side research execution agent — IMPLEMENTED (D3):** HC-183 adds `POST /v1/research-executions` and `GET /v1/research-executions/{execution_id}` to each Hospital Node, and `/health` now advertises `research_execution`. The node checks the Governance authorization envelope against its identity, requested organizations and variables, and expiry before local access, then runs one bounded preinstalled HbA1c aggregate with encounter-date filters. It returns only controlled aggregate cells with explicit empty, minimum-cell suppression, failed, denied, invalid, conflict, and not-found states; local patient references never leave the node. The submitted artifact and arbitrary code are not executed. State is in memory, callers and the Governance envelope are not authenticated, and sandboxing remains HC-186. Demo responses carry `mocked: true` because their local source is the canonical fictional HC-005 repository; the agent is not presented as production-ready.

Production build, lint, and Vitest suite pass; the review flow was driven in headless Chrome (validation errors, confirmation, recorded decision, cleared pending badge, audit event, reset) with no console error. In `http` mode, failures are handled (HC-147): connection errors, `503`, and timeouts are retried once with the same `query_id` within a 5-second budget, and a node that failed 3 consecutive queries is paused for 30 seconds and reported `not_asked` with `circuit_open` (in memory). Capability discovery (HC-143) calls each registered node's `GET /v1/federation/node` over real HTTP on request and keeps the latest result in memory. A running Hospital Node is reported `discovered`; one not running is `unreachable`. Temporary sync authorization (HC-144): before any node is asked under a synchronization decision, the service checks it with the Governance Node over real HTTP and asks only the organizations Governance authorizes. No Governance Node exists yet, so live sync-basis queries return `503` and ask no node; the authorized path is covered by tests only. - **Governance hospital approval, synchronization, and research decisions — MOCKED (D1):** a decision recorded in the Governance Portal (HC-073, HC-076, HC-078) is built in the browser and kept in local, in-memory portal state with a `decision_recorded` audit event, both labelled simulated.
